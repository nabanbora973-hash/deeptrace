# DeepTrace — multi-signal face-swap forensics

**Three streams of evidence, one explainable verdict.**

DeepTrace detects face-swap ("deepfake") video by fusing three independent families of
forensic evidence — spatial, frequency and temporal — into a single **calibrated,
auditable** decision. Every face in the frame is tracked and scored separately, so a
swapped face can no longer hide behind a genuine one. Every verdict ships with the artefacts that produced it: an evidence
heat-map, a per-frame timeline, the frequency spectrum, and the exact arithmetic of the
fusion score.

It runs offline on a CPU, exposes a REST API, a CLI, a browser console, and a PDF report
generator. No cloud service, no GPU, no black box.

```
  video / image
        │
        ▼
  ingest ──► frame sampling (evenly spread, deterministic)
        │
        ▼
  face tracking  ──► detect *every* face → associate across frames → 256² crop per identity
        │
        │      (per face, independently — see "Multiple faces" below)
        ├──────────────► SPATIAL     seam energy · noise discontinuity · chroma · sharpness
        ├──────────────► FREQUENCY   high-freq ratio · spectral slope · GAN peaks · DCT blocks
        └──────────────► TEMPORAL    flicker · identity jitter · rPPG blood-pulse
                                    │
                                    ▼
                        reliability-weighted fusion
                     logit(p) = b + Σ wᵢ·rᵢ·(2sᵢ − 1)   per face
                                    │
                                    ▼
                     clip verdict = worst-case face
        ┌───────────────────────────┴───────────────────────────┐
        ▼                    ▼                     ▼            ▼
   REAL / FAKE /       heat-map +          REST JSON      PDF report
   INCONCLUSIVE        timeline +
                       spectrum
```

## How the verdict is built

### 1. Spatial stream — what the swap leaves in the image plane
Measured on the aligned 256² crop, all as scale-free ratios:

| feature | signal |
|---|---|
| `noise_uniformity` | a pasted face has unnaturally *uniform* sensor-noise texture relative to real surroundings |
| `noise_inconsistency` | noise level breaks at the face boundary |
| `seam_contrast` | gradient ridge along the blending boundary |
| `colour_mismatch` | Lab chroma offset between swapped region and background |
| `sharpness_mismatch` | double resampling leaves the pasted region softer |

### 2. Frequency stream — what the generator leaves in the spectrum
Hann-windowed FFT of the crop:

`hf_ratio` (excess high-frequency energy), `spectral_slope` (real faces fall off ~1/f²),
`peak_prominence` (periodic GAN grid peaks), `angular_peakiness` (checkerboard concentration),
`dct_blockiness` (8×8 DCT high-frequency statistics).

### 3. Temporal stream — what a frame-by-frame generator cannot fake
`flicker` (instability of the per-frame artifact score), `identity_jitter` (face-descriptor
discontinuity between frames), and **rPPG** — remote photoplethysmography. A real face carries
a blood pulse in its green channel; generated skin does not. The stream reports a **support**
value and is *down-weighted* when a clip is too short to support pulse evidence, because
absence of evidence is not evidence of authenticity.

### 4. Fusion — additive, therefore auditable
Each stream is mapped to a synthetic-likelihood score with a logistic model over standardised
features, then:

```
logit(p) = bias + Σ  wᵢ · rᵢ · (2·sᵢ − 1)          rᵢ = stream reliability
```

Every reported contribution is a term of that sum, so the UI and the PDF reconstruct the
score exactly — no post-hoc saliency approximation. Verdict bands leave an explicit
**review band**: anything between the two thresholds is reported `INCONCLUSIVE` instead of
being forced into a confident answer.

**Where that band comes from.** The width is not a constant in the code — it is selected from
out-of-fold scores by `deeptrace/abstain.py` and written into `calibration.json` under
`abstention`, together with the full risk–coverage curve that justifies it. Three policies:

| policy | flag | question it answers |
|---|---|---|
| `cost` (default) | `--policy cost --cost-fp 10 --cost-fn 3 --cost-review 2` | what is the cheapest expected cost per clip, given that a false accusation is 10× a miss? |
| `coverage` | `--policy coverage --target-coverage 0.85` | abstain as little as possible while still deciding ≥ 85% of clips |
| `error_bound` | `--policy error_bound --alpha 0.20` | widen until the **95% upper bound** on error among decided clips (Clopper–Pearson) is ≤ α |

The chosen band, its coverage, and that upper bound are reported in the JSON, the PDF banner and
the app tooltip, so the number a reviewer sees always comes with its justification.

## Results

All numbers below are produced by `train/fit_calibration.py` and
`train/eval_protocol.py` and are reproducible with `bash scripts/rebuild.sh`.
AUC comes with a percentile bootstrap 95% CI (1000 resamples).

### Held-out, in-corpus (5-fold out-of-fold, 42 clips — 18 real / 24 swap)

| model | AUC | 95% CI | EER |
|---|---|---|---|
| spatial only | 0.912 | [0.805, 0.988] | 0.167 |
| frequency only | 0.766 | [0.595, 0.907] | 0.285 |
| temporal only | 0.634 | [0.459, 0.787] | 0.403 |
| **fused** | **0.933** | **[0.837, 0.995]** | **0.118** |

Fusion beats every single stream — that is the whole argument for a multi-signal design.
The temporal stream is weakest here because the corpus clips are 2.4 s long, so its
reliability weight is low by construction.

### Cross-corpus (fit on the standard corpus, evaluated on held-out *subtle* swaps: 22 clips)

| model | AUC | 95% CI | EER | F1 | balanced acc. |
|---|---|---|---|---|---|
| **fused** | **0.990** | **[0.950, 1.000]** | **0.031** | 0.968 | 0.969 |
| spatial only | 1.000 | [1.000, 1.000] | 0.000 | 1.000 | 1.000 |
| frequency only | 0.833 | [0.625, 0.975] | 0.292 | 0.857 | 0.875 |
| temporal only | 0.641 | [0.257, 1.000] | 0.500 | 0.914 | 0.750 |

**No real clip was accused**: 0 false positives out of 6 authentic clips. The cost of that
conservatism is visible: at the shipped thresholds 6 of 16 subtle swaps fall below the `REAL`
boundary instead of being flagged, and on this shifted corpus almost nothing lands near the
boundary, so abstention does not rescue them — coverage stays at 100% and accuracy on decided
clips is 0.727. AUC says the *ranking* survives the shift; the absolute probability does not
(the equivalent threshold on this corpus is 0.047). That is a recalibration problem, not a
threshold-width problem, and it is the honest reason the next step is a real-corpus refit.

### Where the review band sits (out-of-fold, 42 clips)

The cost policy prefers **width 0.03** — a narrower band than the 0.12 that was previously
hard-coded. The curve is the argument:

| band | coverage | errors | error │ decided | FPR | FNR | 95% upper bound | expected cost/clip |
|---|---|---|---|---|---|---|---|
| 0.53–0.53 (no band) | 100% | 5 | 12% | 6% | 17% | 23% | 0.52 |
| **0.50–0.56 (shipped)** | **90%** | **3** | **8%** | **0%** | **14%** | **19%** | **0.40** |
| 0.41–0.65 (old fixed band) | 76% | 2 | 6% | 0% | 11% | 18% | 0.62 |
| 0.29–0.77 | 24% | 0 | 0% | 0% | 0% | 26% | 1.52 |

Reading it honestly:

- **No band at all** decides every clip but produces one false accusation (FPR 6%) — the single
  most expensive error in a forensic setting.
- **0.03 removes that false accusation** for 10% abstention, at the lowest expected cost.
- **Widening further buys nothing**: the remaining 3 errors are not near the boundary, so the band
  only abstains on more clips (cost triples by width 0.30) without removing an error.
- With 42 clips the tightest **certifiable** guarantee is a 19% upper bound on error among decided
  clips — anything better is a statement about the sample size, not about the detector. That is
  exactly what a FaceForensics++ refit is for.

| clip | verdict | p(fake) | spatial / frequency / temporal |
|---|---|---|---|
| `authentic_call.mp4` | REAL | 0.006 | 0.18 / 0.39 / 0.50 |
| `authentic_still.jpg` | REAL | 0.003 | 0.18 / 0.20 / 0.37 |
| `oneshot_swap.mp4` | FAKE | 0.871 | 0.97 / 0.82 / 0.91 |
| `oneshot_swap_still.jpg` | FAKE | 0.799 | 0.93 / 0.83 / 0.37 |
| `subtle_swap.mp4` | FAKE | 0.899 | 0.95 / 0.95 / 0.73 |
| `swap_compressed.mp4` | FAKE | 0.895 | 0.97 / 0.87 / 0.91 |
| `two_faces_swap.mp4` | FAKE | 0.675 (face #1) · 0.006 (face #2) | 0.78 / 0.90 / 0.50 for the flagged face |

The image cases are instructive in both directions. `oneshot_swap_still.jpg` scores 0.37 on
the temporal stream — a single frame carries no temporal evidence at all — and is still caught
from spatial + frequency alone. `two_faces_still.jpg` is the same construction with a
well-blended pane and is **missed**: at 0.33 the worst face never reaches the threshold,
because the evidence that carries that swap in video (flicker across frames) is simply absent
from one frame. Both are reported as measured; a single frame is a weaker question than a clip.

## Multiple faces in one frame

Averaging evidence across all faces is wrong on two counts: a swapped face next to a genuine
one gets diluted, and a two-person frame looks like a different kind of input to every
downstream statistic. So DeepTrace scores faces **separately** and merges them at the *verdict*
level, not the *feature* level.

**1. Detect every face.** `FaceLocator.detect_all` returns all faces above a size floor
(Haar by default, YuNet if `data/models/face_detection_yunet.onnx` is present), largest first,
with IoU **and containment** suppression — Haar likes to fire twice on one face, and a small
box sitting inside a big one is a duplicate, not a second person (`_suppress_nested`).
One canonicalisation is applied per frame, driven by the largest face, so crops from the same
frame share a scale and their spectra stay comparable.

**2. Track identities.** `deeptrace/tracking.py` associates detections across the sampled
frames with a greedy, fully auditable cost:

```
cost = ‖Δcentre‖ / mean_side  +  0.55·|log size ratio|  −  0.90·IoU  −  0.20·appearance
```

Hard gates stop identity switches (displacement, size ratio), frames where a face is briefly
missed are bridged (`TRACK_MAX_GAP`), and a `fallback` window (the centred crop used when a
frame has no detection) can never be merged into a real face. Appearance similarity is a
*tie-breaker*, not a gate: OpenCV detectors return a tight box on one frame and a loose box on
the next, and those two crops correlate poorly while still being the same person — exactly the
bug that shredded one face into five short tracks during development (§"Scale canonicalisation"
below has the sibling story).

**3. Score each face, then take the worst.** Each track gets its own three streams, its own
calibration and its own evidence ledger. The clip verdict is the **worst-case face**, because
one manipulated identity is enough to make a recording suspect, and disagreement is reported
instead of averaged:

```json
"faces": {
  "count": 2, "analysed": 2, "max_simultaneous": 2, "primary_track": 1, "verdict_track": 1,
  "tracking": { "association": "greedy centre-distance + size-ratio + appearance",
                "min_track_frames": 4, "frames_sampled": 48 },
  "aggregate": { "strategy": "worst-case face", "verdict": "FAKE", "p_fake": 0.694,
                 "track_id": 1, "p_fake_min": 0.006, "p_fake_max": 0.694,
                 "disagreement": 0.688, "agreement": "1 of 2 faces flagged" },
  "tracks": [
    { "track_id": 1, "frames": 48, "continuity": 1.0, "role": "primary",
      "verdict_source": true, "verdict": { "verdict": "FAKE", "p_fake": 0.694, "...": "..." },
      "streams": { "spatial": {}, "frequency": {}, "temporal": {} } },
    { "track_id": 2, "frames": 48, "continuity": 1.0, "role": "secondary",
      "verdict": { "verdict": "REAL", "p_fake": 0.006, "...": "..." } }
  ]
}
```

Faces seen in fewer than `MIN_TRACK_FRAMES` sampled frames are listed with `analysed: false`
and a reason — never scored, never silently dropped. Two extra artefacts come out of this:
`faces.png` (every face annotated on the frame with its own verdict) and `tracks.png` (face
identity across the sampled timeline). In the console, click a face to switch the evidence
ledger, fusion arithmetic and temporal diagnostics to that identity.

| knob | default | meaning |
|---|---|---|
| `DEEPTRACE_MAX_FACES` | `3` | faces analysed per clip (compute bound) |
| `DEEPTRACE_MIN_TRACK_FRAMES` | `4` | sampled frames a face needs before it is scored |
| `DEEPTRACE_TRACK_MAX_GAP` | `3` | sampled frames a face may disappear and return as the same identity |

## Honest limitations (read this before quoting a number)

1. **The calibration is fitted on a synthetic corpus.** No licensed deepfake dataset ships
   with this repo, so the shipped decision layer is fit on composites produced by
   `demo/make_dataset.py`. The *measurements* are real statistics of your input; the mapping
   from measurements to `p(fake)` is what needs real data.
2. **Synthetic separability ≠ real-world accuracy.** A one-shot composite leaves much cruder
   traces than a modern diffusion or GAN face-swapper. Expect the numbers above to fall on
   FaceForensics++ / Celeb-DF / DFDC.
3. **Multi-face is per-frame-crop evidence, not face *recognition*.** Tracks are maintained by
   motion and low-frequency appearance — enough to keep two co-present people apart, not to
   re-identify someone who leaves the frame and returns (they can appear as two identities).
   Faces seen in only a handful of frames are listed but not scored, and only the worst-case
   face drives the clip verdict.
4. **The pulse head is untested on this corpus** — synthetic clips genuinely have no
   heartbeat, so its features have zero variance here and the fit disables them (documented in
   `data/calibration.json` → `training.inactive_features`). It activates on real footage.
5. **Adversarial post-processing wins.** Heavy denoising, rescaling, re-encoding or deliberate
   artifact suppression can defeat artifact-based detectors, including this one.
6. **A clean verdict is not proof of authenticity.** Provenance metadata (C2PA), source
   verification and human review remain the stronger evidence class. DeepTrace produces
   *forensic evidence*, not proof.

### Refitting on real data (one command each)

```bash
# 1. put clips in samples/dataset/real/*.mp4 and samples/dataset/fake/*.mp4
python train/extract_features.py --data /path/to/corpus --out data/features_real.csv
# 2. fit; prints held-out AUC/EER per stream and fused, writes data/calibration.json
python train/fit_calibration.py --features data/features_real.csv
# 3. cross-dataset protocol: fit on FF++, evaluate on Celeb-DF
python train/eval_protocol.py --features data/features_ffpp.csv \
                              --cross-corpus data/features_celebdf.csv --json data/eval_celebdf.json
```

The runtime consumes whatever JSON is in `data/calibration.json` — no code change, and
`GET /api/calibration` always shows the document actually in force.

## Design decisions worth defending

- **Reliability weighting instead of blind averaging.** A 12-frame clip cannot prove the
  absence of a pulse; the temporal stream is scaled down rather than trusted, and the reason
  is reported to the user (`reliability_note`).
- **An explicit abstain state.** A binary detector on degraded social-media video manufactures
  false confidence. The review band makes "I don't know, escalate" a first-class outcome.
- **Scale canonicalisation.** The first version of this repo keyed on resolution-dependent
  features and failed on a clip rendered at a different size; the face crop is now normalised
  to a canonical pixel size before any statistic is computed, and the training corpus spans
  two capture resolutions. That bug is documented in `demo/make_dataset.py`.
- **Everything is data, not code.** Thresholds, feature means/sds, coefficients and fusion
  weights live in one versioned JSON document with a model card attached.

## Hosted deployment notes (v1.2.1)

- **Rate limit:** `POST /api/analyze` allows `DEEPTRACE_RATE_LIMIT` requests (default 8) per
  `DEEPTRACE_RATE_WINDOW` seconds (default 300) per IP. One clip costs 30-70 s of CPU on a free
  instance, so an unauthenticated endpoint is otherwise a denial-of-service button.
- **Upload cap:** `DEEPTRACE_MAX_UPLOAD_MB` (default 60).
- **Ephemeral runs:** free tiers keep `DEEPTRACE_WORK_DIR` on local disk. A restart wipes
  `/data/runs`; download the JSON if you need the record.
- **No face = abstention:** when no real face is tracked (or only the fallback window was
  available), the verdict is `INCONCLUSIVE` with `no_face: true` - never `REAL`. A missed face is
  missing evidence, and clearing a clip on it would be the worst possible false negative.
- **Pin OpenCV:** `opencv-python-headless>=4.8,<5`. OpenCV 5 removed `cv2.CascadeClassifier`,
  which the face locator uses; without the pin every analysis returns HTTP 500.
- **Speed:** lower `DEEPTRACE_MAX_FRAMES` (default 48) to 16 for interactive use on a free
  instance; accuracy on short clips barely moves.
